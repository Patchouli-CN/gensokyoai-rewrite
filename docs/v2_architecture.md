# GensokyoAI v2 架构设计

> 状态：草案（审过之前不写代码）
> 原则：这份文档本身也遵守它定义的规矩——能一句话说清的器官不分三节。

## 0. 设计公理（v1 真机实测换来，每条有实验背书）

1. **人味死在中间人手里**。A/B 实证：同模型，裸对话像角色，过"决策层写剧本 +
   表达层念剧本"就像秘书。v2 没有任何"替模型写剧本"的器官。
2. **读房间是像人的分水岭**。聊天语域（短、脆、口语）只能从聊天记录传染，
   无法从人设卡写出来。开口的模型必须看见房间，不是只看 @ 它的那句。
3. **append-only 聊天流是天然的缓存友好结构**。只追加，前缀永不变——
   高缓存命中率是数据结构的副产品，不需要专门的缓存优化。
4. **小模型不会替你收拾格式**。工具调用走"喊话提取 + 自教学错误"（v1 已
   验证的链路），设计不押注模型的格式纪律；也绝不写方言正则补丁——方言
   无限，补丁就无限，没把握就报错教学，让模型自己重写。
5. **可选层必须能拆**。每个器官都是旋钮：云端强模型来了逐层关，本地小
   模型犯病了逐层开。最小内核 = Room + Mind。

## 1. 核心数据结构：房间（Room）

一条 append-only 的事件流，**唯一事实源**。所有器官读它，所有产出写它。

```
{now, events: [...]}
  event = 群友消息 | 角色发言 | 工具结果 | 系统注记（记忆召回/整理标记）
```

- 平台事件由 Eyes 追加；角色发言由 Mouth 追加；工具结果由工具回合追加；
  记忆召回以「系统注记」形态出现在房间里——模型像人一样"看到"了自己
  想起来的事，而不是读到一份检索报告。
- 渲染给模型时带 `now`（每条消息时间戳）——时间感知零成本，根治
  "现在几点了"类问题。

## 2. 器官图

```
            清醒期（task-positive）                    静息期（DMN）
                                            ┌──────────────────────────┐
 平台 ─Eyes─→ Room ─Attention─→ Mind ─Mouth─→ 平台        │ 睡眠整理（静默侧链）        │
                ↑      ↑          ↑↓工具回合   │  · 窗口压力 → 记忆压缩      │
                └──────┴──────────┘          │  · OOC 审查（白天的发言）   │
                Memory（检索→房间注记）        │  · 短→长期记忆归档/蒸馏     │
                                            │  · 用量/费用日结           │
                                            └──────────────────────────┘
        Nerve（计费 / 健康诊断 / 命令子模块）：横跨两期，纯工程
```

### Eyes（感知层，纯工程，v1 搬运）
平台适配 → 追加事件到 Room。队列合流、攒批合并等逻辑不变。

### Attention（精力/注意力）
仿人类注意力：每个房间一个档位（高/中/低），由消息速率 + 最近是否被 @ 驱动。
调制三样东西：
- **开口阈值**：冷群少说，热群正常接话
- **读房深度**：热群读全场，冷群只扫最近几句
- **记忆写入强度**：热群多记，冷群附和不记
不做任何文本加工——它只回答"要不要醒"。

### Mind（直接开口，无大脑层）
读（房间 + 人设）→ 接话。一次模型调用 = 一次开口，**零决策延迟**。
- 需要外部信息时**自己喊话工具**：框架提取 → 执行 → 结果写回房间 →
  模型看到结果接着说（v1 喊话链路搬运：提取/自教学错误/SSRF 门禁/知识站）。
- 没有 action_hint、没有初稿、没有 JSON 决策协议。
- 人设 = 角色卡 system；房间 = user。完。

### Mouth（嘴层，纯工程 + ReplyStyle）
投递（流式/缓冲）+ 场景风格出口（pure_dialogue/tavern/rpg：叙事视角、
叙述许可、开场白开关）。v1 搬运。

### Memory（记忆）
- 写入：按 Attention 强度分级写入
- 召回：以房间注记形态注入（不是元数据块）
- 整理：**窗口压力触发**（快满了 → 等群里安静的间隙静默压缩整理；
  不在群热时抢延迟——人也是闲下来才整理记忆）

### DMN（静息期整理，默认模式网络）
群进入安静时段（深夜/早晚高峰以外的低谷，按活动规律动态判定）时启动：
- 记忆压缩（窗口压力之外的定期整理）
- **OOC 审查**：白天说过的话夜里反刍，查出戏、记模式——不进热路径
- 短期→长期记忆归档/蒸馏
- 用量/费用日结

### Nerve（神经束，纯工程保留）
计费配额 / 健康诊断中心（/doctor）/ 命令子模块。与语音路径零耦合。

## 3. 一条消息的生命周期（热路径）

1. Eyes 把平台消息追加进 Room
2. Attention 判：要不要醒（冷群可能直接略过）
3. Mind 读（人设 + 房间）开口；需要查证则喊话工具 → 结果回 Room → 接着说
4. Mouth 按 ReplyStyle 投递回平台，发言追加进 Room
5. Memory 按注意力强度记一笔

清醒期全程无决策会议、无元数据文档、无剧本。

## 4. 旋钮清单（按模型能力逐层开关）

| 旋钮 | 本地小模型 | 云端强模型 |
| --- | --- | --- |
| Attention 裁判（LLM 判要不要醒） | 开（规则+裁判） | 可关（规则即可） |
| 工具调用 | 喊话提取 | 原生 tool_calls（探测自动切换） |
| OOC 审查（DMN 内） | 开 | 关 |
| ReplyStyle | 按场景 | 按场景 |
| 记忆召回注入量 | 保守 | 宽松 |

## 5. 迁移路径

1. `v2/` 目录从零写新包（不带旧代码；旧包原地留作参考书）
2. v1 资产逐项搬运验证：记忆系统 / 喊话工具链 / ReplyStyle / hub /
   计费 / 健康 / 命令 / nb2 插件（eyes 适配）
3. v2 跑通并实测人味后：删旧包，`v2/` 内容移到根目录

## 6. 明确不做的（反目标）

- 任何"替模型写剧本"的机制（action_hint / 初稿 / 决策元数据进人设提示词）
- JSON 接力思考协议、思考链管线
- 方言正则抢救、空结果回退链——没把握就报错教学（穿过模型，不绕过模型）
- 一个 key 一个 Struct 式的形式主义
- 为"以后可能有用"预留的抽象
